# Balanced v3.4：同步团队转移与stay动作

独立实验目录：`wall_aware_hybrid3_balanced_v3_4`。
本版修复采样和动作语义，保留11维输入、二值relay特征、v3.3通信奖励权重、
学习率、2000条单机器人transition预采集和1024次critic预热。
不包含集中式critic、GRU、角色头或专家行为克隆。

## 改动

- 训练与推理共用`team_rollout.py`：先固定所有观测和动作，全部移动、感知后，
  按最终通信分量交换信息，再更新图、奖励、通信计时和下一观测。
  下一观测直接用于下一次决策，不重复生成。初始化时同步实际分散起点的感知和belief，
  初始覆盖不领取探索进度奖励。
- 传感更新使用独立地图副本，避免已断连机器人通过共享数组获得新感知结果。
  信息传播读取同一份快照，避免机器人循环顺序影响消息转发。
- 候选槽位0显式保留stay；合法节点编号0不再作为padding哨兵。
  actor/Q共用不修改输入的mask，并逐样本处理兜底动作。
- 重叠前沿发现的奖励由发现者均分，消除顺序执行下的先行动者优先。
  无新感知的stay不领取原节点探索效用，无信息增量的stay不领取汇合效用；
  团队进度、通信与停滞奖励继续正常计算。
- 权重0.5的KL约束作用于合法移动动作的条件分布，不约束stay概率。
  没有移动候选的样本不计入该KL。
- 196步是任务截止时间：完成与耗尽时间都停止bootstrap，但只有覆盖完成
  才标记成功和领取完成奖励。日志分别记录成功、stay比例和时间耗尽。
- Replay前15个字段保持原SAC布局；字段15保存`episode/team_step/robot_id`，
  字段16保存前沿、节点探索效用、汇合效用、路程、团队奖励、通信奖励、探索进度、
  停滞惩罚、完成标志和时间耗尽标志。随机采样仍按单机器人transition计数。

## 启动与权重

AutoDL从项目根目录启动：

```bash
conda activate mrobot
python -u driver.py
```

默认`LOAD_MODEL=False`、`LOAD_POLICY_ONLY=True`，仅加载
`model/wall_aware_hybrid3_balanced_v2_3520/checkpoint.pth`中的策略。
旧实验Q、优化器、温度和Replay不能迁移；v3.4完整续训会检查同步转移版本。
历史目录和checkpoint不覆盖。本地环境名为`BLMRE_py38`。

## 评估入口

默认使用固定50张验证图：

```bash
python test_driver.py
```

可指定候选归档权重：

```bash
IR2_EVAL_MODEL_PATH=model/wall_aware_hybrid3_balanced_v3_4/checkpoint_960.pth python test_driver.py
```

冻结候选后，显式选择最终测试集：

```bash
IR2_EVAL_SPLIT=test python test_driver.py
```

每个地图/种子仅调度一次；执行失败写入CSV的`status/error`，不替换为其他地图。
地图读取失败也不再静默替换。存在执行失败时不报告完整集合平均达标结果。
验证和测试输出目录分开，CSV含地图文件名、集合和种子。

## 比较边界与验证状态

同步交互、起点感知和动作合法性与旧版不同。旧权重可以初始化或在新环境评估，
但新结果不能直接与旧环境结果当作同条件比较。需要重新建立基线。
唯一模型硬门槛仍为平均个体探索率≥99%、平均全连通率≥90%。

本版保留了现有11维观测和20步通信预算，因此没有解决全部历史状态混叠，
也没有改造原有依赖仿真真值的断连计时/旧位置失效判定；不宣称已完成真实机器人
可部署的局部信息建模。

按用户要求，本次修改未运行测试、完整回合或训练。代码变更不代表模型已达标。
